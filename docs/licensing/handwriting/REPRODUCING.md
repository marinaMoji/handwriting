# Reproducing the training data, the model and the staged package

Everything is regenerated by one script from two pinned upstream downloads. Outputs go to `experiments/hzw-package/`, which git ignores. Nothing is uploaded and `models/` is not touched.

## Requirements

- CMake and a C++17 compiler (to build `zinnia_learn` and `handwriting_eval` from this repository)
- Qt 6 (only for `handwriting_eval`)
- Python 3.10 or later with `numpy` (used by `ml/tegaki.py`)
- git, curl
- 6 to 20 minutes of CPU time (measured: 341 s and 1,048 s on the same machine under different load) and 150 MB of disk

## Steps

```bash
./scripts/fetch_models.sh
```

```bash
git clone https://github.com/chanind/hanzi-writer-data.git experiments/hanzi-writer-data
```

```bash
git -C experiments/hanzi-writer-data checkout 68d10a4b21150cae5e1ebbd223eed289cf32d90c
```

```bash
cmake -S . -B build && cmake --build build --target zinnia_learn handwriting_eval
```

```bash
python3 scripts/build_hzw_model_package.py build
```

The `build` command:

1. checks the Hanzi Writer commit, the Tegaki XML and tarball hashes, and both licence texts against [sources.json](sources.json);
2. writes `work/training-data/hzw-derived.ja.s` (Arphic PL) and `work/training-data/tegaki-derived.ja.s` (LGPL-2.1), each with its modification notice, and `work/combined.ja.s`;
3. runs `zinnia_learn` on the combined corpus;
4. compares the corpus and model hashes with the pinned ones and stops if they differ;
5. stages `stage/marinamoji-handwriting-ja-hzw-experimental/` with `MANIFEST.json`, and verifies it.

Options: `--reuse-model PATH` stages an existing model without retraining; `--allow-hash-mismatch` stages anyway and records the differences in the manifest.

## Checking the result

```bash
python3 scripts/build_hzw_model_package.py verify
```

```bash
python3 scripts/build_hzw_model_package.py eval
```

`verify` needs only the Python standard library. `eval` loads the staged model through the normal recognizer (as `handwriting-ja.model` in a temporary models directory, with the production traditional Chinese model) and runs `handwriting_eval` on the local `samples/`. Expected on the 214 development samples: Japanese top-1 71.0, top-5 84.1; Both top-1 71.0, top-5 85.5 (see [../../hanzi-writer-experiment.md](../../hanzi-writer-experiment.md)).

## Limits of reproducibility

- The corpora are produced with integer arithmetic after rounding and should be identical on any platform.
- The model hash has been reproduced only on macOS arm64 with AppleClang. Training is deterministic (fixed shuffle seed), but floating-point results and `std::shuffle` output can differ between compilers and standard libraries. On another platform a different model hash is possible; use `--allow-hash-mismatch` and compare recognition results instead.
- The conversion script must not be given `--prefer-sample-chars`; the build script never passes it.
